Function Calling 完整生命周期
STEP 1
定义工具
编写 JSON Schema，声明函数名、描述、参数类型、required 字段
→
STEP 2
模型决策
LLM 读取 Schema，决定是否调用、调用哪个函数、传入什么参数
→
STEP 3
提取调用意图
解析响应中的 tool_use / function_call 块，取出函数名和参数
→
STEP 4
参数校验
用 JSON Schema / Pydantic / Zod 验证参数合法性，拦截错误调用
→
STEP 5
执行函数
调用真实业务逻辑（API / DB / 计算），捕获执行异常
→
STEP 6
返回结果
把执行结果（或错误）封装回 tool_result，送入下一轮对话

Claude vs OpenAI — 关键差异速查
维度 Claude (Anthropic) OpenAI
定义字段 input_schema parameters
调用块类型 tool_use tool_calls[].function
参数格式 直接 dict（已解析） JSON 字符串（需 json.loads）
结果回传 role user（tool_result 块） tool
强制调用 tool_choice: {type:"tool", name:"fn"} tool_choice: {type:"function", function:{name:"fn"}}
并行调用 支持（content 多个 tool_use） 支持（tool_calls 数组）
流式工具调用 支持（input_json_delta 事件） 支持（tool_calls delta）
JSON Schema 完整字段参考
基础类型
string
文本。可加 enum / minLength / maxLength / pattern（正则）
number
浮点数。可加 minimum / maximum / multipleOf
integer
整数。约束同 number，但不含小数
boolean
true / false，无额外约束
array
列表。需配 items 定义元素类型，可加 minItems / maxItems / uniqueItems
object
嵌套对象。需配 properties，建议加 additionalProperties: false
null
空值，通常配合 anyOf: [type, null] 表示可选字段
关键约束字段
required
必填字段列表，未出现在列表中的字段均为可选
enum
枚举值，模型只能从列表中选取，用于状态/类型字段
description
⭐ 最重要！引导模型理解参数含义，影响生成质量
default
默认值，可选字段未提供时使用
anyOf
满足任一 Schema 即可，常用于联合类型
additionalProperties
false 时禁止未声明字段，生产环境推荐开启

{ "type": "function", ← OpenAI 外层多一个 type "function": { "name": "get_stock_quote", "description": "查询指定股票的实时行情数据...", "parameters": { ← OpenAI 用 parameters "type": "object", "properties": { "symbol": { "type": "string", "description": "股票代码，如 '600519.SH' 或 'AAPL'", "pattern": "^[A-Z0-9]{1,6}(\\.(SH|SZ|HK))?$" }, "fields": { "type": "array", "items": { "type": "string", "enum": ["price", "change_pct", "volume"] } }, "currency": { "type": "string", "enum": ["CNY", "HKD", "USD"] } }, "required": ["symbol"], "additionalProperties": false, "strict": true ← OpenAI Structured Output 专用 } } }
Schema 设计黄金法则
  • description 是最重要的字段，比类型约束影响更大
  • 状态/类型参数必须用 enum，不要用 free-form string
  • 可选参数提供 default，减少模型猜测负担
  • 嵌套层级控制在 3 层内，太深模型容易漏字段
  • 加 additionalProperties: false 防止模型添加幻觉字段
  • description 里写调用时机（"当用户询问...时调用"）
  • required 字段太多 → 降低调用成功率
  • 用 string 存多个值 → 改用 array 或 enum
  • 参数命名模糊（如 data、info）→ 用具体名
  • 单个工具功能太多 → 拆分成多个职责单一的工具
  • 工具数量超过 10 个 → 性能下降，考虑按场景分组
  • description 太长 → 保持 100 字内，重点突出
Claude — 完整 Python 实现
import anthropic, json from typing import Any client = anthropic.Anthropic() # ① 工具定义 tools = [ { "name": "get_stock_quote", "description": "查询股票实时行情，支持A股/港股/美股", "input_schema": { "type": "object", "properties": { "symbol": {"type": "string", "description": "股票代码如 600519.SH"}, "currency": {"type": "string", "enum": ["CNY","USD","HKD"]} }, "required": ["symbol"] } }, { "name": "get_financial_report", "description": "获取公司最新财报数据", "input_schema": { "type": "object", "properties": { "symbol": {"type": "string"}, "period": {"type": "string", "enum": ["Q","Y"], "default": "Q"} }, "required": ["symbol"] } } ] # ② 工具路由表（函数注册表） def get_stock_quote(symbol: str, currency: str = "CNY") -> dict: # 真实场景：调用行情 API return {"symbol": symbol, "price": 1850.0, "change_pct": "+2.3%", "currency": currency} def get_financial_report(symbol: str, period: str = "Q") -> dict: return {"symbol": symbol, "revenue": "¥380亿", "net_profit": "¥190亿"} TOOL_REGISTRY = { "get_stock_quote": get_stock_quote, "get_financial_report": get_financial_report, } # ③ 核心 Agent 循环 def run_agent(user_query: str) -> str: messages = [{"role": "user", "content": user_query}] while True: response = client.messages.create( model="claude-sonnet-4-6", max_tokens=4096, tools=tools, messages=messages ) # ④ 判断停止原因 if response.stop_reason == "end_turn": # 模型直接回答，无工具调用 return next(b.text for b in response.content if b.type == "text") if response.stop_reason != "tool_use": raise RuntimeError(f"Unexpected stop_reason: {response.stop_reason}") # ⑤ 提取所有 tool_use 块（支持并行调用） tool_uses = [b for b in response.content if b.type == "tool_use"] tool_results = [] for tool_use in tool_uses: try: fn = TOOL_REGISTRY[tool_use.name] result = fn(**tool_use.input) ← Claude 的 input 已是 dict tool_results.append({ "type": "tool_result", "tool_use_id": tool_use.id, "content": json.dumps(result, ensure_ascii=False) }) except Exception as e: tool_results.append({ "type": "tool_result", "tool_use_id": tool_use.id, "is_error": True, ← 告诉模型执行失败 "content": f"Error: {str(e)}" }) # ⑥ 把模型回复和工具结果一起追加到 messages messages.append({"role": "assistant", "content": response.content}) messages.append({"role": "user", "content": tool_results}) # 继续循环，让模型基于工具结果生成最终答案 # 调用 answer = run_agent("茅台今天涨了多少？帮我看下最新财报") print(answer)

// Tool 定义（对应 Claude input_schema） record StockQuoteInput( @JsonProperty("symbol") String symbol, @JsonProperty("currency") String currency ) {} // 工具注册 Service @Service public class ToolExecutorService { private final Map<String, Function<Map<String,Object>, Mono<String>>> registry; public ToolExecutorService(StockApiClient stockClient) { registry = Map.of( "get_stock_quote", input -> { String symbol = (String) input.get("symbol"); return stockClient.getQuote(symbol) .map(q -> toJson(q)) .onErrorReturn("""{"error":"行情服务暂时不可用"}"); } ); } public Mono<String> execute(String toolName, Map<String,Object> input) { Function<Map<String,Object>, Mono<String>> fn = registry.get(toolName); if (fn == null) { return Mono.just("""{"error":"未知工具: """ + toolName + "\"}"); } // 参数校验 + 执行 return Mono.fromCallable(() -> validateInput(toolName, input)) .flatMap(fn) .timeout(Duration.ofSeconds(10)) .onErrorResume(TimeoutException.class, e -> Mono.just("""{"error":"工具调用超时"}")); } }
三层参数校验架构
层 1 — Schema 级校验
jsonschema / Pydantic / Zod
验证类型、required、enum、pattern、min/max。在执行函数之前拦截，成本最低。
层 2 — 业务级校验
在函数内部
股票代码是否在交易所存在、日期是否在有效范围、用户是否有权限调用此工具。
层 3 — 防御级校验
注入防护 / 安全边界
拦截 Prompt Injection（工具参数里藏指令）、SQL Injection、路径穿越等攻击向量。
完整校验代码 — Python
from pydantic import BaseModel, validator, Field from jsonschema import validate, ValidationError import re # ── 层 1：Pydantic Schema 校验 ── class StockQuoteParams(BaseModel): symbol: str = Field(..., description="股票代码") currency: str = Field("CNY", description="货币") fields: list[str] = Field(default_factory=lambda: ["price", "change_pct"]) @validator("symbol") def validate_symbol(cls, v): # 层 1：格式检查 pattern = r'^[A-Z0-9]{1,6}(\.(SH|SZ|HK))?$' if not re.match(pattern, v.upper()): raise ValueError(f"无效股票代码格式: {v}") return v.upper() @validator("currency") def validate_currency(cls, v): if v not in ["CNY", "USD", "HKD"]: raise ValueError(f"不支持的货币: {v}") return v @validator("fields", each_item=True) def validate_fields(cls, v): allowed = {"price", "change_pct", "volume", "pe_ratio"} if v not in allowed: raise ValueError(f"不支持的字段: {v}") return v # ── 层 2：业务校验 ── def validate_business_rules(params: StockQuoteParams) -> None: # 检查股票是否在支持的交易所 if params.symbol.endswith(".SH") and params.currency == "USD": raise ValueError("A股不支持USD计价，请使用CNY") # 检查代码是否真实存在（查缓存/数据库） if not stock_code_exists(params.symbol): raise ValueError(f"股票代码不存在: {params.symbol}") # ── 层 3：安全校验 ── def sanitize_input(raw_input: dict) -> dict: # 检查 Prompt Injection 特征 dangerous_patterns = [ r'ignore.*previous.*instructions', r'system.*prompt', r', r';\s*(DROP|DELETE|UPDATE)\s+TABLE' # SQL Injection ] flat = json.dumps(raw_input).lower() for pattern in dangerous_patterns: if re.search(pattern, flat, re.IGNORECASE): raise SecurityError(f"检测到潜在注入攻击: {pattern}") return raw_input # ── 统一校验入口 ── def validate_tool_call(tool_name: str, raw_input: dict) -> BaseModel: sanitize_input(raw_input) # 层 3 VALIDATORS = {"get_stock_quote": StockQuoteParams} model_cls = VALIDATORS.get(tool_name) if not model_cls: raise ValueError(f"未知工具: {tool_name}") params = model_cls(**raw_input) # 层 1（Pydantic） validate_business_rules(params) # 层 2 return params
错误类型全景
SCHEMA_MISMATCH
参数类型/格式不符
模型传入了 Schema 未声明的字段，或类型不对（如 string 传了 number）
→ 用 Pydantic / jsonschema 校验后返回 is_error:true + 错误描述，让模型重试
MISSING_REQUIRED
必填参数缺失
用户没提供足够信息，模型无法确定 required 字段的值
→ 返回错误："缺少必填参数 symbol，请提供股票代码"，模型会向用户追问
TOOL_NOT_FOUND
调用了不存在的工具
模型幻觉或 Schema 更新不同步，调用了未注册的函数名
→ 路由层做名称白名单校验，返回 "工具 xxx 不存在" 而非崩溃
EXECUTION_ERROR
函数执行失败（下游异常）
行情 API 超时、数据库连接断开、第三方服务返回 5xx
→ 捕获异常，返回结构化错误；让模型决定是否重试或给用户友好提示
TIMEOUT
工具调用超时
函数执行时间超过预设阈值（通常 5~15s），需要中断
→ asyncio.timeout / reactor 超时控制，返回超时错误让模型感知
INFINITE_LOOP
工具调用死循环
模型反复调用同一工具且结果没有改善（常见于参数错误时模型不断重试）
→ 设置最大迭代次数（如 10 轮），超出后强制退出并告知用户
完整错误处理代码
import asyncio from dataclasses import dataclass class ToolError(Exception): def __init__(self, code: str, message: str, retryable: bool = False): self.code = code self.message = message self.retryable = retryable # ── 错误分类处理器 ── def handle_tool_error(tool_use_id: str, error: Exception) -> dict: if isinstance(error, ValidationError): msg = f"参数校验失败: {error.errors()}" elif isinstance(error, asyncio.TimeoutError): msg = "工具调用超时（>10s），请稍后重试" elif isinstance(error, KeyError): msg = f"工具未找到: {error}" elif isinstance(error, PermissionError): msg = "权限不足，无法调用此工具" else: msg = f"工具执行失败: {str(error)}" print(f"[TOOL_ERROR] {tool_use_id}: {msg}") # 记录日志 return { "type": "tool_result", "tool_use_id": tool_use_id, "is_error": True, "content": json.dumps({ "error": msg, "retryable": isinstance(error, (asyncio.TimeoutError, ConnectionError)) }) } # ── 防死循环的 Agent 循环 ── MAX_ITERATIONS = 10 async def safe_agent_loop(user_query: str) -> str: messages = [{"role": "user", "content": user_query}] iteration = 0 consecutive_errors = 0 while iteration < MAX_ITERATIONS: iteration += 1 response = await async_claude_call(messages) if response.stop_reason == "end_turn": return extract_text(response) tool_results = [] all_failed = True for tool_use in extract_tool_uses(response): try: params = validate_tool_call(tool_use.name, tool_use.input) result = await asyncio.wait_for( execute_tool(tool_use.name, params), timeout=10.0 ) tool_results.append(make_tool_result(tool_use.id, result)) all_failed = False consecutive_errors = 0 except Exception as e: tool_results.append(handle_tool_error(tool_use.id, e)) consecutive_errors += 1 # 连续 3 次全部失败，主动退出 if consecutive_errors >= 3: return "抱歉，工具服务暂时不可用，请稍后再试。" messages.append({"role": "assistant", "content": response.content}) messages.append({"role": "user", "content": tool_results}) return f"超过最大迭代次数({MAX_ITERATIONS})，任务终止。"
模式 1：工具选择策略（tool_choice）
三种模式
# auto：模型自决（默认） tool_choice={"type": "auto"} # any：必须调用工具（随便选） tool_choice={"type": "any"} # tool：强制调用指定工具 # → 最强的结构化输出方式 tool_choice={ "type": "tool", "name": "get_stock_quote" }
使用场景
# auto → 通用对话 Agent 适合: 用户意图多样，不确定是否需要工具 # any → 必须获取实时数据时 适合: 明确需要调用外部系统的场景 # tool → 结构化信息提取 适合: 替代 JSON Mode，100% 保证结构 示例: 从用户话语提取股票代码、 日期范围、操作意图等结构化字段
模式 2：并行工具调用（Parallel Calls）
# 用户：帮我同时看茅台和宁德时代的行情 # 模型会在一次响应里返回两个 tool_use 块 Response.content = [ {"type": "tool_use", "id": "t1", "name": "get_stock_quote", "input": {"symbol": "600519.SH"}}, ← 茅台 {"type": "tool_use", "id": "t2", "name": "get_stock_quote", "input": {"symbol": "300750.SZ"}}, ← 宁德 ] # ✅ 正确处理：并发执行，同时回传结果 import asyncio async def handle_parallel(tool_uses): tasks = [execute_tool(t.name, t.input) for t in tool_uses] results = await asyncio.gather(*tasks, return_exceptions=True) tool_results = [] for tool_use, result in zip(tool_uses, results): if isinstance(result, Exception): tool_results.append(handle_tool_error(tool_use.id, result)) else: tool_results.append(make_tool_result(tool_use.id, result)) return tool_results # 一次性回传所有结果 # ❌ 错误做法：按顺序执行，性能差 2~N 倍 for t in tool_uses: result = await execute_tool(t.name, t.input) # 串行！

生产环境检查清单
  • 工具 description 写清楚"何时调用"的触发条件
  • 所有工具参数做三层校验（Schema/业务/安全）
  • 并行工具调用用 asyncio.gather 而非 for 循环
  • Agent 循环设置最大迭代次数（推荐 10-20）
  • 每次工具调用设置超时（推荐 5-15s）
  • is_error: true 正确传回，让模型感知失败
  • 工具执行结果控制在合理大小（<50KB）避免上下文爆炸
  • 流式调用时用 input_json_delta 累积参数
  • OpenAI arguments 是字符串，记得 json.loads
  • production 环境监控工具调用频率和成功率
  • 工具超过 10 个时性能下降，考虑动态注入工具
  • 不要在工具结果里返回 Markdown 格式文本
