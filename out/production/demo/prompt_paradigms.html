Zero-shot Prompting
不给任何示例，直接让模型完成任务。
依赖预训练时学到的通用能力，最简单也最常用。
核心原理
[你只需要清晰描述任务] 将下面的英文翻译成中文： "The quarterly report shows a 15% increase in revenue." → 季度报告显示收入增长了 15%。
进阶：加角色 / 格式约束
你是一位资深的代码审查专家。 审查以下 Python 代码，指出潜在问题，输出格式为 JSON： ```python def get_user(id): return db.query("SELECT * FROM users WHERE id=" + id) ``` → {"issues": [{"type": "SQL注入", "line": 2, "severity": "critical"}]}
✅ 适合用
  • 简单分类 / 情感分析
  • 摘要 / 翻译
  • 通用问答
  • 格式转换（有明确规则）
  • 快速原型验证
❌ 不适合
  • 多步骤数学推理
  • 需要特定输出风格
  • 领域专业术语密集
  • 小模型复杂任务

Few-shot Prompting
在 Prompt 里给 2~8 个示例（input→output），让模型学会模式。
比 Zero-shot 更精确，比微调更灵活。
标准结构
# 示例 1 输入：这个产品太棒了！ 输出：正面 # 示例 2 输入：质量很差，不推荐。 输出：负面 # 示例 3 输入：还行，没有特别惊喜。 输出：中性 # 待预测 输入：物流速度可以，但包装损坏了。 输出：→ 负面
示例选择技巧（影响效果最大）
技巧 1：示例要覆盖边界情况，不要只给"典型正确" 技巧 2：示例格式要和期望输出格式完全一致 技巧 3：示例数量：2~8 个，太多反而干扰（特别是小模型） 技巧 4：示例顺序有影响 — 最后一个示例权重最高（近因效应） 技巧 5：动态 Few-shot：从向量库里检索和当前 query 最相似的示例
✅ 适合用
  • 特定格式输出（JSON/表格）
  • 领域特定分类
  • 风格迁移、语气统一
  • 小模型能力提升
  • 没有微调资源时
❌ 注意
  • 示例太少且质量差 → 比 Zero-shot 更差
  • 示例有偏差 → 模型会学偏
  • Context 窗口有限时要节省
  • 推理类任务建议配合 CoT

Chain-of-Thought (CoT)
让模型把中间推理步骤显式写出来，再给出最终答案。
Google 2022 年论文证明：CoT 能让复杂推理准确率提升 50%+。
Zero-shot CoT（最简单：加一句话）
Roger 有 5 个网球，又买了 2 罐，每罐 3 个。他现在共有多少个？ 让我们一步步思考。 ← 这句话就够了！ Roger 原有 5 个。 买了 2 罐 × 每罐 3 个 = 6 个。 5 + 6 = 11 个。 答案：11 个。
Few-shot CoT（示例里直接展示推理过程）
# 示例 Q：食堂早上有 23 个苹果，用了 20 个做午饭，又买了 6 个，还剩几个？ A：开始有 23 个。做午饭用了 20 个，还剩 23-20=3 个。 又买了 6 个，共 3+6=9 个。 答案：9 个。 # 问题 Q：停车场有 3 排，每排 10 辆，走了 7 辆来了 2 辆，现在多少辆？ A：原有 3×10=30 辆。走了 7 辆剩 23 辆。来了 2 辆共 25 辆。 答案：25 辆。
为什么有效？
直接回答：模型必须在一次 forward pass 里"压缩"所有推理 写出步骤：每个 token 生成时都能"看到"前面的推理结果 → 把复杂问题分解成一系列简单问题 → 可解释、可调试、错误可追溯
✅ 最有效场景
  • 数学应用题 / 计算推理
  • 逻辑题 / 因果分析
  • 代码 debug（写出排查思路）
  • 医疗/法律诊断推理
  • 多步骤规划
❌ 效果有限
  • 简单分类任务（过度设计）
  • 小于 7B 的小模型
  • 对延迟敏感的场景
  • 纯事实检索（配合 RAG 更好）

Self-Consistency
多次运行 CoT（高 Temperature），得到多条推理路径，
对最终答案投票取最多数。用冗余换准确率。
核心流程
同一问题
→
×N 次采样
T=0.7~1.0
→
N 条推理路径
→
提取各路径答案
→
多数票✓
示例：同一道题三条推理路径
Q：一件衣服原价 200，打八折后再优惠 20 元，最终价格？ 路径 A：200×0.8=160，160-20=140 ✓ → 答案：140 路径 B：200×0.8=160，再减20，160-20=140 ✓ → 答案：140 路径 C：八折是160，优惠券20，最终140元 ✓ → 答案：140 投票结果：140（3/3）→ 最终答案：140 元 ✅ --- 如果路径C走偏了 --- 路径 C'：200-20=180，再打八折=144 ✗ → 答案：144 投票结果：140（2票）vs 144（1票）→ 仍选 140 ✅
N 次采样如何选择？
N=3：低成本，错误容忍度一般（1/3 错误会被纠正） N=5：平衡点，论文中常用值 N=10+：高准确率，适合关键决策，成本显著上升 经验法则：先用 CoT+N=1 评估基础准确率 - 基础准确率 <60%：问题出在 Prompt，不是采样次数 - 基础准确率 60-80%：N=5 有明显提升 - 基础准确率 >80%：N=3 够用，成本收益更好
✅ 值得用
  • 高精度数学/逻辑推理
  • 医疗诊断辅助决策
  • 金融风险计算
  • 考试题自动评分
  • 离线批处理任务
❌ 不适合
  • 实时对话（延迟 N 倍）
  • 成本敏感项目
  • 开放性创意任务（无唯一答案）
  • 简单任务（浪费）

ReAct（Reason + Act）
推理与行动交替进行：Thought → Action → Observation → Thought…
是现代 AI Agent 的核心范式，解决 LLM 知识静态问题。
完整交互示例
Q：Claude Sonnet 4 的最大 Context Window 是多少？现在是否支持 Vision？ Thought 1：这是关于最新模型的问题，我的训练数据可能过时， 需要查询最新文档。 Action 1：web_search("Claude Sonnet 4 context window vision 2025") Observation 1：搜索返回 Anthropic 官方文档，显示相关规格... Thought 2：已获得官方数据，可以整合回答用户问题了。 Action 2：web_fetch("https://docs.anthropic.com/...") Observation 2：获取详细规格页面内容... Thought 3：信息充足，现在可以给出准确答案。 Answer：根据最新官方文档，[具体数据]...

↩ 循环直到任务完成
可接入的 Action（工具）类型
搜索类： web_search / RAG 检索 / 数据库查询 执行类： Python 代码执行 / Shell 命令 / API 调用 读写类： 文件读写 / 数据库增删改查 / 邮件发送 感知类： 截图分析 / 浏览器操控 / 表单填写 协作类： 调用其他 Agent / 子任务委派
vs 纯 CoT 的核心区别
纯 CoT： 知识来自模型参数，可能过时/幻觉，无法执行操作 ReAct： 知识来自实时工具，准确且可追溯，能改变外部世界 纯 CoT 回答"今天 A 股涨了多少"：可能编造数据 ❌ ReAct 回答"今天 A 股涨了多少"：调用股票 API → 真实数据 ✅
✅ ReAct 的主场
  • 需要实时信息的问答
  • 多步骤自动化任务
  • 代码生成 + 执行验证
  • AI Agent / 工作流自动化
  • 你们的 ai-service 健康助手
❌ 注意事项
  • 工具调用失败需要错误处理
  • 循环次数需要有上限（防死循环）
  • 延迟比纯生成高
  • 工具权限要严格控制
