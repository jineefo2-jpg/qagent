# 第一部分 · BRD（业务需求）

## 1. 业务背景与价值主张

### 1.1 用户是谁

单一个人量化投资者。A 股市场，中小资金规模（设计规格 §12 以"千万"为容量重估线，推断当前规模低于此）。具备编程与统计能力，但没有机构级数据与工程资源。

这是**一个人的产品**，不是团队产品。后文的四个"角色"是同一个人的四顶帽子（见 §2.1），任何多用户、权限、协作类需求本期直接否决。

### 1.2 要解决的问题

用户的核心痛点不是"没有策略想法"，而是**无法判断自己的想法是不是自欺**。

具体表现为三层：

| 层 | 问题 | 后果 |
|---|---|---|
| 事实层 | 拿不到可信的历史事实。财报用报告期而非公告日、股票池不含退市股、宏观指标按所属期而非公布日 —— 三者任意一个错，回测就在用未来数据 | 回测 Sharpe 系统性虚高，且**无声**。用户不会收到任何报错 |
| 验证层 | 有了想法无法证伪。样本内反复调参、看到好结果就上线 | 上线即失效，把过拟合当 alpha 用真金白银验证 |
| 执行层 | 从"想法"到"周一早上下什么单"之间有一大段手工劳动 | 每周 10 小时以上投入；执行时点、价位靠临场判断，引入行为偏差 |

### 1.3 为什么现有方案不够用

| 现有方案 | 它给了什么 | 对本用户的硬伤 |
|---|---|---|
| 人工看盘 / 自选股 | 完全可控、零依赖 | 人脑无法对 5000+ 只股票做横截面比较；无法回测；决策随情绪漂移；每周时间成本 10h+ |
| 雪球 / 跟单大 V | 零门槛、有社区讨论 | 信号不可回测、不可归因；发布者的历史业绩本身有幸存者偏差（亏损组合会被删除）；跟单者与发布者的成本、时点、仓位均不一致，实际收益与展示收益无关 |
| 券商投顾 / 基金投顾 | 持牌合规、省心 | 调仓逻辑黑盒，无法查看因子暴露；无法施加自定义约束（行业上限、换手上限）；管理费 + 申赎费长期侵蚀收益；无法回答"这次调仓是因为什么" |
| 第三方量化平台（聚宽 / 米筐 / 掘金等） | 现成数据 + 回测引擎，上手快 | **PIT 质量不可验证**：用户无法确认平台财报字段是否按公告日对齐、默认股票池是否含退市股；策略与数据锁在平台内，无法本地复现；全 A 15 年级别的回测受免费额度限制；不含研报知识库与深度报告能力 |
| 自己裸写 pandas | 完全自由、完全本地 | 前视偏差极难自查——它不报错，只会给出一个更好看的结果。没有工程护栏，写得越多漏得越多 |

**共同缺口**：以上方案没有一个能让用户回答"**我凭什么相信这个回测数字**"。

### 1.4 价值主张

> 把 A 股全市场 15 年的**可验证事实底座**与**防自欺回测护栏**，转化为每周五收盘后的一份可直接执行的调仓清单，并让每一条买卖都能被解释、被复现、被追溯。

三个价值支柱，按重要性排序：

1. **可信度（第一位）** — PIT 数据 + 防自欺五闸。用户真正需要的不是"一个策略"，而是"**我知道这组数字没有骗我**"。这是全部后续价值的地基，也是与所有现有方案的唯一实质差异。
2. **决策省时** — 每周一次、单次 15 分钟以内的执行动作，替代每周 10 小时的看盘与手工筛选。
3. **可解释** — 每条 order 带因子贡献分解 + 自然语言归因。用户能理解模型为什么这么选，从而判断是否接受，而不是盲从黑盒。

**产品定位的诚实表述**：本产品的核心价值是**降低自欺概率**，不是承诺收益。任何 PRD 都无法承诺投资收益，因此本文全部成功指标落在**过程可验证性**上，不含任何收益率目标。

### 1.5 不做会怎样（机会成本）

| 不做 | 后果 |
|---|---|
| 不做 P1 | 用户继续在第三方平台或自建脚本上回测，每次策略上线前都无法回答"这个 Sharpe 有没有前视"。最坏结果：用真金白银为一个不存在的 alpha 买单。含前视的因子回测 Sharpe 常虚高 2 倍以上 |
| 做了 P1 不做 P2 | 有可信数据但无法验证任何想法。P1 的全部投入变成沉没成本 |
| 做了 P1+P2 不做 P3 | 用户获得的是"研究能力"而非"决策产品"。每周仍需手工跑脚本、手工算权重、手工定挂单价。省时价值为零 |
| 不做 P4/P5 | 用户失去归因与深度报告能力，但**决策链路完整可用**。这两期是价值增强，不是价值必需（见 §10 Q1、Q2） |
| 不做 P6 | 用户在命令行看清单。可用，但周一早上的执行体验差（见 FR-P6-05 的场景分析） |

### 1.6 成功指标（可度量）

| 编号 | 指标 | 目标值 | 度量方式 | 生效里程碑 |
|---|---|---|---|---|
| M-01 | 数据可信度 | 设计规格 §11 的 7 条 P1 断言全部通过 | 自动化脚本，通过/不通过二值 | M1 |
| M-02 | 外部抽查一致性 | 用户随机抽 3 个历史时点 × 3 只股票，在外部数据源核对，一致率 100% | 用户手工抽查，记录在验收单 | M1 |
| M-03 | 引擎正确性 | `reversal_20`、`turnover_20` 在 2010–2019 区间十分层年化收益呈显著单调 | 自动化断言（Spearman 秩相关 \|ρ\| ≥ 0.8） | M2 |
| M-04 | 研究迭代速度 | 单因子全市场 15 年十分层回测 < 30 秒 | 计时断言 | M2 |
| M-05 | 决策耗时 | 从打开清单到券商 App 下单完成 ≤ 15 分钟 / 周，连续 4 周 | 用户自记录 | M3 |
| M-06 | 信号可执行率 | 清单中标的在 T+1 可成交（非一字板、非停牌）比例 ≥ 90% | 系统自动统计 | M3 |
| M-07 | 挂单区间准确率 | 用户实际成交价落在 `limit_price_range` 内的比例 ≥ 80% | 用户回填成交价后系统统计 | M3 |
| M-08 | 信号采纳率 | 用户实际执行的 order 条数 / 清单总条数 ≥ 70% | 成交回写数据统计 | M3 |

M-07 与 M-08 是产品健康度的核心信号：M-07 低说明挂单区间给得不准（执行层缺陷）；M-08 低说明用户不信任信号（信任层缺陷）。两者都必须能被观测到，因此**成交回写（FR-P3-07）是 P0**。

## 2. 用户角色与核心用户故事

### 2.1 角色定义

同一个自然人，在四种场景下的四种行为模式。**不为角色做权限隔离，不做多用户体系。**

| 角色 | 场景 | 使用频率 | 最关心 |
|---|---|---|---|
| R1 研究者 | 验证策略想法、调因子、跑回测 | 密集期每天，稳定后每月 | 回测正确性、IC、五闸判定、迭代速度 |
| R2 执行者 | 看清单、在券商 App 下单 | 每周一次，时间窗口极窄（周一 9:15–9:25） | 买什么卖什么、多少钱挂单、先下哪笔 |
| R3 复盘者 | 月度 / 季度回顾 | 每月 | 实盘 vs 回测偏离来源、策略是否失效 |
| R4 运维者 | 数据更新、故障处理 | 每周至少一次 | 数据到哪一天了、能不能信、坏了怎么办 |

### 2.2 用户故事

#### R1 研究者

| 编号 | 用户故事 |
|---|---|
| US-R1 | As 研究者, I want 用一条命令对任一因子跑 2010–2025 全市场十分层回测并拿到 IC / ICIR / 分层年化收益, So that 我能在 1 分钟内判断这个想法值不值得继续投入 |
| US-R2 | As 研究者, I want 每次回测结果自动附带参数哈希与数据截止日, So that 三个月后我能复现出完全相同的数字，而不必怀疑是自己改过参数 |
| US-R3 | As 研究者, I want 系统在我不小心用到未来数据时**直接报错**而不是给我一个漂亮结果, So that 我不会把前视偏差当成 alpha |
| US-R4 | As 研究者, I want 一键跑防自欺五闸并得到"通过 / 未通过"的明确判定, So that 我不会因为"看起来还行"就把策略推上生产 |
| US-R5 | As 研究者, I want 系统告诉我这是第几次跑样本外, So that 我不会在不知情的情况下把样本外污染成样本内 |

#### R2 执行者

| 编号 | 用户故事 |
|---|---|
| US-E1 | As 执行者, I want 周五收盘后自动收到下周一的调仓清单（买 / 卖 / 目标权重 / 挂单价区间）, So that 我周一开盘 15 分钟内照着下完单，不需要临场判断 |
| US-E2 | As 执行者, I want 每条买入标注前三大因子贡献, So that 我能一眼判断这是"便宜"还是"动量"，决定是否手工否决 |
| US-E3 | As 执行者, I want 清单按执行优先级排序, So that 我在集合竞价的 10 分钟窗口里知道先下哪几笔 |
| US-E4 | As 执行者, I want 在某笔单因一字涨停买不进时，系统在下一期清单里明确标注它"未完成"而不是当作已成交, So that 我的真实持仓和系统认为的持仓不会逐周漂移 |
| US-E5 | As 执行者, I want 看到目标总仓位与我实际仓位的差额, So that 我知道是否需要整体加减仓 |

#### R3 复盘者

| 编号 | 用户故事 |
|---|---|
| US-C1 | As 复盘者, I want 每月看到实际净值 vs 回测净值的偏离分解（择时 / 选股 / 执行滑点 / 我手工否决）, So that 我知道跑输是策略的问题还是我自己的问题 |
| US-C2 | As 复盘者, I want 在策略连续多周落在回测分布尾部时收到告警, So that 我能及时判断是策略失效还是正常回撤，而不是等到亏够了才反应 |

#### R4 运维者

| 编号 | 用户故事 |
|---|---|
| US-O1 | As 运维者, I want 每次数据更新后拿到一份校验报告（通过 / 告警 / 阻断 + 缺失区间清单）, So that 我在信号生成之前就知道这周的数据能不能信 |
| US-O2 | As 运维者, I want 数据源失败时系统**拒绝生成信号**而不是用残缺数据硬算, So that 我不会拿到一份基于半截数据的清单 |
| US-O3 | As 运维者, I want 在任何界面都能看到数据落库到了哪一天, So that 我不会把上周的数据当成本周的用 |

# 第二部分 · PRD（产品需求）

## 3. 功能需求清单

### 3.0 编号与优先级规范

- 编号：`FR-P<阶段>-<序号>`，阶段号对应设计规格 §3 的 P1–P6。
- 优先级：`P0` = Must（不做则本迭代无法交付价值）／`P1` = Should（本迭代做，可延后至下一迭代）／`P2` = Could（有余力才做）／`Won't` 见 §7。
- 迭代：M1 = P1 数据底座，M2 = P2 因子与回测，M3 = P3 策略层，M4 = P4 知识库，M5 = P5 LLM 层，M6 = P6 前端。

- FR-P1-09 降 P1：缺资金流数据时，宏观投票退化为 4 指标（设计规格 §6.1 五指标去掉 `north_flow_60`），策略仍可运行；两个资金类因子中 `margin_chg_20` 设计规格自标"待检验"。不是地基。

- FR-P1-17 移至 M4：本期无消费方，公告文本的唯一用途是知识库语料。

### 3.7 Must 集合收敛说明

本期（M1 + M2）共 38 条需求，其中 P0 = 29 条，占比 **76%**。

按常规规则，Must 超过 30% 应主动砍需求。**本 PM 判定该规则在此不适用，理由如下**：

30% 规则的前提是需求集合中存在"锦上添花"项可被剥离。P1/P2 是数据地基与验证地基，特征是**少一块就整体塌陷** —— 缺日历则无法定义交易日，缺涨跌停价则无法判定可交易性，缺公告日则整个 PIT 前提瓦解。人为把地基项标为 Should 只会制造"表面达标、实际必做"的假象，是更坏的管理动作。

**替代收敛手段**：P0 判定标准改为「设计规格 §11 可执行断言的传递依赖闭包」。凡不在闭包内的一律降级。已从 47 条初始候选中砍掉 / 降级 9 条：

| 被砍 / 降级项 | 处置 | 理由 |
|---|---|---|
| 资金流数据 + 2 个资金因子 | P0 → P1 | 宏观投票可退化为 4 指标运行 |
| 行业与风格归因 | P0 → P1 | 本期无消费方 |
| 风险平价权重 | 移至 M3 | 等权是基线，加权需先过五闸 |
| Parquet 冷备 | P0 → P2 | 可靠性增强，非功能必需 |
| 公告文本采集 | 移至 M4 | 本期无消费方 |
| walk-forward 闸 | P0 → P1 | MVP 无可调参数 |
| 参数高原闸 | P0 → P1 | 同上 |
| 多用户 / 权限体系 | Won't | 单人产品 |
| 回测结果 Web 页 | 移至 M6 | M2 用落盘报告顶替 |

**产能兜底降级序列**：若 M1 + M2 无法在预算周期内交付，按以下顺序削减，**禁止全面降质**：

1. 削 FR-P1-16（Parquet 冷备）
2. 削 FR-P1-15（数据源抽象，退化为主源 + 校验源两个硬编码适配）
3. 削 FR-P2-04 + FR-P1-09（资金类因子与数据）
4. 削 FR-P2-12、FR-P2-15、FR-P2-18
5. 削 FR-P2-03 中的 `sue` 与 `accrual`（实现复杂度最高的两个基本面因子）
6. 数据起始日从 2010-01-01 缩至 2013-01-01（样本外区间不变，仅缩短样本内）

**削到第 6 条仍不够，则本期不交付，不做"半个 P1"。** 半个数据底座比没有数据底座更危险，因为它看起来能用。

## 4. 验收标准

### 4.1 覆盖范围说明

本章为 **M1 + M2 的全部 P0 需求**提供 Given/When/Then 验收条件，QA 可直接转为测试用例。M3–M6 的验收条件在对应迭代启动时的 PRD 增补版中给出 —— 现在写死会在迭代过程中被大量改写，是浪费。M3–M6 本章只给出验收要点。

标注 `[规格 §11]` 的条目直接引用设计规格的可执行断言；标注 `[业务补充]` 的为本 PM 增补的业务侧验收。

### 4.3 M2 · 因子与回测引擎验收

**AC-12 · 引擎正确性反测** `[规格 §11 + 业务补充]` — 覆盖 FR-P2-02、FR-P2-08、FR-P2-13

```
Given 数据底座已通过 M1 验收
When  对 reversal_20 与 turnover_20 分别在 **2010-01-01 至 2019-12-31** 区间跑十分层回测

And   最高层与最低层的年化收益差 > 年化波动的 0.5 倍
And   若不满足，判定为数据或引擎缺陷，不得以"市场变了"结案

验收窗口被本 PM 从"全区间"收窄为"2010–2019"，理由见 §10 Q4：2020 年后因子衰减是可能的真实市场变化，用它做引擎正确性判据会诱导工程师"调数据直到跑出结果"—— 那是最危险的一种过拟合。2020 年至今的分层结果单独记录为「因子衰减观察」，不作为放行条件。

Given 因子注册表中的全部因子函数
When  运行静态检查脚本
Then  所有因子函数的第一个参数名为 as_of_date
And   脚本以非零退出码报告任何违例，可接入提交前检查
```

**AC-18 · 回测性能与可复现** `[规格 §11 + 业务补充]` — 覆盖 FR-P2-21、M-04

```
Given 全市场 15 年数据已入库
When  运行一次周频全市场回测
Then  单次运行耗时 < 60 秒

When  运行单因子全市场 15 年十分层回测
Then  单次运行耗时 < 30 秒

Given 一次回测已完成并记录了参数哈希与数据截止日
When  在数据未更新的前提下，用相同参数哈希再跑一次
Then  两次输出的净值序列逐点相等（浮点容差 1e-9）
And   两次输出的全部评估指标相等
```

**AC-19 · 回撤预期管理** `[业务补充]` — 覆盖 FR-P2-11、RK-10

```
Given 一份回测报告
When  用户打开报告
Then  报告在净值曲线之前或同屏展示：最大回撤幅度、最大回撤发生区间、**最长回撤持续期（从峰值到重新创新高的自然日数）**
And   这三个数字与年化收益具有同等的视觉权重，不得折叠或置于附录
```

年化收益让用户开始使用产品，最长回撤持续期决定用户能否坚持到策略生效。后者比前者更重要且更容易被隐藏。

### 4.4 M3–M6 验收要点（详细条件随迭代增补）

| 迭代 | 验收要点 |
|---|---|

| M6 | 信号清单在 375px 宽度视口下无横向滚动即可读完全部 order 的代码、方向、数量、挂单区间；免责声明在信号看板首屏、回测报告页首、每份 LLM 报告页脚三处常驻，不可关闭 |

## 5. 非功能需求

### 5.1 性能

| 编号 | 项 | 目标 | 依据 |
|---|---|---|---|
| NFR-01 | 全市场 15 年周频回测 | 单次 < 60 秒 | 设计规格 §11 |
| NFR-02 | 单因子全市场 15 年十分层回测 | 单次 < 30 秒 | 研究者的想法验证节奏。超过 30 秒，用户会停止试想法 —— 这是研究效率的悬崖点 |

| NFR-04 | 首次全量建库 | < 8 小时，且**必须支持断点续跑** | 数据源限流是现实约束，一次性跑完不现实 |

| NFR-07 | 回测报告页 | < 5 秒 | M6 |

### 5.2 数据时效性

| 编号 | 项 | 要求 |
|---|---|---|
| NFR-08 | 日线与估值 | 交易日 20:00 前完成入库与校验（收盘后留足重试窗口） |

### 5.3 可靠性与降级行为

**核心原则：宁可不出信号，不出错信号。**

| 编号 | 场景 | 行为 |
|---|---|---|
| NFR-12 | 阻断级校验失败（日线缺口、公告日缺失、公布日缺失、涨跌停价缺失） | 不生成信号；发出告警；保留上期清单并标注「已过期，勿执行」；报告失败项与缺失区间 |
| NFR-13 | 告警级校验失败（复权因子跳变未匹配、双源偏差超限） | 正常生成信号，但清单顶部标注降级原因与受影响标的数；受影响标的在清单中单独标记 |
| NFR-14 | 主数据源不可用 | 日线部分由校验源补齐并标注来源；**财报与宏观无替代源，直接触发 NFR-12 阻断**。不做任何插值、外推或沿用上期值的兜底 |
| NFR-15 | 单条数据缺失（个别股票个别日） | 该股票当期被排除出股票池，记入排除清单，不做填充 |
| NFR-16 | 回测中途异常 | 失败即中止并输出已完成区间，不返回部分结果冒充完整结果 |

NFR-14 与 NFR-15 的共同约束：**任何形式的数据兜底猜测都被禁止**。缺失就是缺失，缺失导致的排除必须可见。

## 6. 迭代路线图

### 6.1 里程碑与用户可感知价值

| 里程碑 | 范围 | 用户可感知的产出物 | 用户可感知的价值 |
|---|---|---|---|
| **M1** | P1 数据底座 | 《数据体检报告》+ 历史时点查询命令 | "我可以查任意历史日期当天真实存在的股票池和当时已披露的财报，并且我亲手在外部数据源上抽查过，它是对的。" |
| **M2** | P2 因子库与回测引擎 | 《因子体检报告》+ 五闸判定单 + 落盘回测报告 | "我第一次亲手验证了 A 股短期反转真实存在；我也第一次看到一个自己觉得不错的想法被 shuffle 闸拦下来。" |
| **M3** | P3 策略层 | 每周一份可执行调仓清单 | **产品上线时刻。** "周五晚上我收到下周一要下的单，周一早上照着下完，15 分钟。" |
| **M4** | P4 知识库 | 带发布日期的检索结果 | "复盘 2021 年的信号时，我知道我读的这份研报是不是当时就有的。" |
| **M5** | P5 LLM 层 | 归因解释 + 风险排查报告 | "每条买卖都有人话解释；买入前我能看到这家公司有没有明显的雷。" |
| **M6** | P6 前端 | 信号看板 + 移动端清单 + 回测报告页 | "在手机上看着清单下单，不用连电脑。" |

### 6.2 P1/P2 是纯基建，用户看不见任何东西 —— 为什么必须先做

**反向论证**：假设先做能看见的部分（P3 策略层 + P6 前端），用户会在两个月内拿到一个漂亮的信号看板。但这个看板底下的数字是有前视偏差的 —— 财报按报告期而非公告日对齐、股票池不含退市股。用户看到一条回测年化 40% 的净值曲线，然后拿真金白银去执行。

**结论：建在错地基上的可见成果，危害大于没有成果。** 因为没有成果时用户会保持怀疑；有了漂亮成果，用户会停止怀疑。这个产品的第一价值是"降低自欺概率"，先做前端等于在第一天就制造了最大的一次自欺。

顺序不可调整。

### 6.3 如何让用户在 M1/M2 也能看到进展

三个手段，全部已作为需求写入 §3：

**手段一 · 每期交付一个用户能读能验的产出物**

- M1 交付《数据体检报告》（FR-P1-13）+ 历史时点查询能力（FR-P1-11）。这不是给工程师看的日志，是给用户看的一页纸结论。
- M2 交付《因子体检报告》+ 五闸判定单（FR-P2-22、AC-16）。每一闸有明确的三值结论，不是一堆图表。

**手段二 · 把验收变成 demo**

设计规格 §5.6 用 A 股已知异象反测引擎 —— 这同时是技术验收项和用户可感知的成果。

- M1 demo 剧本：用户报出一个历史日期（如 2015-06-12），系统列出当天真实可买的股票池，其中包含若干只如今已退市的股票。用户在外部行情软件抽查 3 只，核对上市日期与退市日期。**这个 5 分钟的演示，是用户第一次真切感受到"这套东西和第三方平台不一样"。**
- M2 demo 剧本：跑 `reversal_20` 十分层，看到单调递减的柱状图；然后故意构造一个纯随机因子跑一遍，看到 shuffle 闸把它拦下。**一正一反两个演示，比任何进度汇报都有说服力。**

**手段三 · 用户是验收方，不是等待方**

每个里程碑设置「抽查仪式」（AC-11）：用户随机抽 3 个数据点在外部数据源核对，核对通过才算验收通过。这把用户从"等交付的人"变成"参与验收的人"，M1/M2 期间用户每周都有具体动作可做。

### 6.4 反模式警告

**不要为了"让用户看见"而在 M1/M2 提前做半个前端。**

半个前端 = 双倍工作量（M6 要重做一遍）+ 错误的信任感（用户看到界面会以为产品能用了）。M1/M2 的产出物形态就是**报告与命令行**，这是正确的形态，不是妥协。

## 7. 不做什么（Won't）

### 7.1 设计规格 N1–N6 的产品语言翻译

**N1 · 不预测个股绝对价格或点位**

- 对用户意味着：你**永远不会**在本系统里看到"茅台目标价 2000 元"。系统只会说"在当前 4800 只股票的横截面里，它排第 12"。
- 为什么：绝对价格预测在数学上不可实现。系统只做相对排序 + 风险预算。
- 如何自行补足：如果你需要一个心理目标价，那是你的主观判断，系统不代劳。清单里的挂单价区间是**执行价格区间**，不是目标价，不要混淆。

**N2 · 不做 A 股自动下单**

- 对用户意味着：每周一你必须自己在券商 App 里手工下 5–15 笔单，耗时约 10–15 分钟，且必须在 9:15–9:25 的集合竞价窗口内完成（见 §10 Q8）。
- 为什么：**这是合规约束不是技术能力问题。** 券商不向个人开放合规交易 API，程序化交易需事先报备。
- 如何自行补足：清单提供挂单价区间与执行优先级；可利用券商 App 的批量委托或条件单功能压缩操作时间。
- **配套风险**：手工执行必然产生"系统认为的持仓"与"实际持仓"的偏差。因此成交回写（FR-P3-07）是 P0，不是可选功能。

**N3 · LLM 不参与买卖决策**

- 对用户意味着：LLM 说"这只股票基本面很好"**不会改变它的任何权重**。你看到的报告是对既有信号的解释，不是新的信号来源。
- 为什么：LLM 输出不可回测、不可复现，一旦进入决策链路，整个回测体系失效。
- 如何自行补足：如果你被某份报告说服想手工加仓某只股票，那是你的主观决策 —— **请单独记账，不要混入策略仓位**，否则归因分析会完全失效，你将永远无法判断跑输是策略问题还是自己的问题。

**N4 · 不做日内或分钟级策略**

- 对用户意味着：你无法用本系统做 T+0 或打板。系统一周只说一次话。
- 为什么：周频调仓已定，分钟数据对周频决策无边际价值。
- 如何自行补足：如需短线交易，另开账户手工操作，**不要与策略仓位混在同一账户**，否则净值追踪与归因作废。

**N5 · 宏观择时层不使用机器学习**

- 对用户意味着：仓位曲线会显得"钝" —— 不会精准逃顶，也不会精准抄底，只会在趋势明确时缓慢加减仓。
- 为什么：月频 15 年只有约 180 个样本点，任何机器学习模型在这个样本量上都是过拟合。
- 如何自行补足：接受这个钝感，它是刻意设计的。20% 的仓位下限是防止择时失败造成极端后果的保险。

**N6 · 不改动现有券商交易通道**

- 对用户意味着：现有的美股 / 港股下单能力不受本项目影响，也不会被 A 股模块复用。
- 如何自行补足：美股走现有通道，A 股走清单 + 人工执行，**两套账本分开记，不要合并计算净值**。

### 7.2 本 PM 额外声明的 Won't

| 项 | 理由 |
|---|---|
| 多用户 / 权限 / 协作体系 | 单人产品。四个"角色"是同一个人的四顶帽子 |
| 实时行情推送 | 周频策略不需要 |
| 原生移动 App | M6 只做移动端可读的 Web 页面（FR-P6-02），一个页面解决问题 |
| 期货 / 期权 / 可转债 / 港股通标的 | 本期只做 A 股股票 |
| 资金规模 > 1000 万的容量优化 | 超出当前规模，届时需重新评估流动性约束 |
| 对外提供服务、发布信号给第三方、社交分享功能 | **合规红线。** 无牌照向他人提供荐股服务存在法律风险 |
| 策略参数的自动寻优 / AutoML | 与防自欺五闸的设计意图直接冲突 |

| RK-01 | **策略失效**（因子拥挤、市场结构变化） | 连续 8 周超额收益落在回测超额分布的 5% 分位以下 | 持续跑输，用户信心崩塌 | 自动降至最低仓位 20% 并暂停执行；回到 M2 重新检验各因子近 2 年 IC。**阈值必须预先约定并写入 FR-P3-11，不允许事后拍脑袋** |

| RK-03 | **市场规则变化**（涨跌停幅度、退市新规、印花税调整、T+0） | 涨跌停价校验项异常，或成本模型与实际成交偏离超阈值 | 回测与实盘系统性偏离 | 规则相关参数全部外置为可配置项；规则变更后重跑近 2 年回测评估影响幅度，超过阈值则暂停执行 |
| RK-04 | **前视偏差潜伏**（最危险 —— 它不报错） | 无自然触发信号，这正是问题所在 | 全部回测结论作废，用户按虚假 alpha 投入真金白银 | 四道防线必须在 M2 全部交付：数据出口签名强制（FR-P1-10）、因子签名静态检查（FR-P2-20）、已知异象反测（AC-12）、shuffle 对照（FR-P2-16）。**四道缺一不可，任一缺失则 M2 不予验收** |
| RK-05 | **人工执行偏差**（漏下单、下错、滑点过大） | 挂单区间命中率 M-07 < 80%，或信号采纳率 M-08 < 70% | 实盘与回测偏离逐周累积 | 成交回写（FR-P3-07）+ 偏离来源分解（FR-P3-10）。**没有回写就无法观测这个风险，这是 FR-P3-07 为 P0 的第二个理由** |
| RK-06 | **过拟合导致上线即失效** | 样本外 Sharpe < 样本内 Sharpe × 0.6 | 上线即亏损 | 五闸判定为硬性放行条件，未过不得进入生产（FR-P2-14 至 FR-P2-18） |
| RK-07 | **单人项目的持续性风险**（用户没时间维护数据） | 数据截止日距当前超过 3 个交易日 | 用陈旧数据出信号 | 自动化日更 + 数据陈旧醒目告警（NFR-11）+ 阻断出信号（NFR-12）。产品侧接受"停用即无害"—— 系统不会在无人看管时自动做任何事 |
| RK-08 | **合规风险**（用户把信号分享给他人） | 无技术触发信号 | 无牌照荐股的法律风险 | 免责声明常驻（FR-P6-04）+ 不对外提供服务的硬约束（NFR-24）+ 措辞约束（NFR-23） |
| RK-09 | **容量风险**（资金增长后小市值容量不足） | 单笔委托金额 / 标的日均成交额 > 1% | 冲击成本失控，实际收益显著低于回测 | 流动性剔除后 20%（设计规格 §4.3）；资金规模超 1000 万时重新评估选股池与持股数 |
| RK-10 | **用户预期落空导致弃用**（在正常回撤期误判为策略失效） | 用户在回撤期停止执行清单 | 产品失败 —— 且是在策略本身没问题的情况下失败 | 首次交付回测报告时强制同屏展示最大回撤、回撤区间、**最长回撤持续期**（AC-19）。让用户在投入前就知道"最坏情况下我要熬多久"。这是最容易被忽略、也最致命的产品风险 |

## 10. 对设计规格中产品价值存疑的部分

以下 8 条是本 PM 对设计规格的产品价值质疑。**技术层面不质疑 —— 设计规格的技术判断均予接受。** 质疑集中在"这件事值不值得做""做了对用户意味着什么""这里的表述会不会导致做错事"。

Q3、Q5、Q6、Q8 需在对应迭代启动前裁决，会改变需求范围。

### Q1 · P4 知识库的严格时点隔离，投入产出比存疑

设计规格 §7 的论证是："复盘 2021 年信号时，LLM 会读到 2023 年的研报，归因全部作废。"

但按 D1，LLM 层是**只读、不参与决策**的。既然归因文本不影响任何一分钱的买卖，"归因作废"的实际损失就只是：用户读到一段时点错乱的解释文字。代价却是给全部语料抽取发布日期、无日期语料全部排除、检索接口改造。

**真正需要严格时点隔离的场景只有一个**：未来把研报文本加工成因子（如研报情绪因子）进入决策链路。那时它是硬需求。

**处置**：FR-P4-02 从 P0 降 P1；用成本约 1/10 的 FR-P4-03（展示发布日期 + 时点不一致警示）先顶上，把完整时点隔离推迟到"文本进入因子"那一天。**撤销条件已写入 §3.4。**

这是典型的"为一个尚不存在的场景付全额成本"。

### Q2 · P5 个股全量级深度报告的价值路径自相矛盾

按 N3 与 D1，LLM 不参与决策。那么用户读完一份深度报告后能做什么？只有两种可能：

- **(a) 什么都不做** —— 报告是消费品，不是决策输入，价值接近于零。
- **(b) 据此手工否决某条信号** —— 但这恰恰破坏策略的统计有效性。策略的 Sharpe 建立在"全部执行"的前提上，挑挑拣拣会引入用户的行为偏差，长期而言通常是负 alpha。

换言之：**深度报告如果真的影响了用户行为，它就违反了 D1 的精神；如果不影响，它就没有价值。**

**处置**：明确 P5 的价值边界为「信任建设 + 负面排查」，而非「决策参考」。P0 收窄为两项：

- `explain_signal`（因子贡献的人话翻译）—— 帮用户建立对模型的理解，属信任建设。
- **风险排查报告**（商誉、质押、减持、审计意见等负面因素专项）—— 纯负向筛查。否决买入是安全方向，不会引入正向选股偏差。

个股全量级报告降为 FR-P5-07（P2）。同时约定：**用户手工否决的信号必须单独记账**（已写入 FR-P3-10），否则归因彻底失效。

### Q3 · 宏观择时：系统里最不可靠的模块，掌握着最大的杠杆

设计规格 §12 自己承认"宏观择时天然弱，样本点少"。5 个指标 × 月频 × 15 年 ≈ 180 个样本点，一个 5 分类投票规则在这个样本量上调出来的东西，统计功效极低。

而它控制的是 **20%–100% 的总仓位** —— 整个组合最大的单一风险敞口。选股层再准，被一个错误的仓位决策乘上 0.2 也就归零了。

**这是本设计中最需要被质疑的一处结构性安排：可靠性最低的模块，杠杆最大。**

**处置建议（需在 M3 启动前裁决）**：把 FR-P3-01 的定义从"宏观择时功能"改为"**仓位管理功能，择时是其中一个可关闭的实现**"。M3 交付时必须同时提供：

1. 择时开关（默认状态由下述检验结果决定）；
2. 两条净值曲线对比：择时 ON vs 固定 80% 仓位，均在样本外区间。

**裁决规则**：若择时版在样本外的 Sharpe 与 Calmar 均未超过固定仓位版，**默认关闭择时**，采用固定仓位。

这是一个可验证的裁决规则，不是一个意见。裁决权在 PM，执行在 M3 验收环节。

### Q4 · "跑不出反转单调性就判定是 bug"—— 方向对，但需要一个逃生口

设计规格 §5.6 的判据是对的：已知异象反测引擎，这是极好的工程实践。

但如果 2021 年后 A 股反转因子确实因量化机构拥挤而衰减，那么用近年数据跑不出单调性可能是**真实的市场变化**。硬性把它定义为"引擎有 bug"，会导致工程师去反复调整数据处理直到跑出想要的结果 —— **这本身就是过拟合，而且是最危险的那一种：调数据，不是调参数。**

**处置**：验收窗口固定为 **2010-01-01 至 2019-12-31**（反转因子在这段区间极其稳健）。这段跑不出单调性 = 确定是缺陷。2020 年至今若出现衰减，单独记录为「因子衰减观察」，不作为引擎正确性判据。

已写入 AC-12。改动很小，但能防住一次严重的自欺。

### Q5 · 输出契约缺成交回写，这是产品缺陷不是设计取舍

设计规格 §6.3 的输出契约是**开环**的：系统发出 orders，但没有任何机制知道用户实际成交了什么。

第二周计算 `current_weight` 时，系统用的是"假设全部按计划成交"的持仓。而实际持仓会因为一字板、用户漏执行、滑点而不同。**这个误差逐周累积，三个月后系统的持仓认知与现实完全脱节，此后所有信号的目标权重差额计算全部作废。**

设计规格 §12 把"无自动执行"列为"设计取舍，非缺陷"。**这个判断需要拆开看**：

- 无自动执行 —— 确实不是缺陷，是合规约束下的正确取舍。
- 无成交回写 —— **是缺陷**。它与自动执行无关，是开环控制系统缺少反馈通路。

两者必须区分。已增补为 FR-P3-07（P0）+ FR-P6-03（P0），并作为 M-07、M-08 两个成功指标的数据来源。

### Q6 · G4 的"每日 / 每周产出清单"与周频调仓自相矛盾

设计规格 §1 的 G4 写"每日/每周产出含时点与价位区间的买卖清单"，但 §0 与 §6.3 全部是周频。

在周频调仓策略下，每日清单没有产品意义 —— 周中不调仓，每天出一份内容相同的清单只是噪音，而且会训练用户忽略通知（这比不发通知更糟）。

**处置**：G4 收敛为**纯周频**。周中只保留「持仓监控 + 异常事件提示」（停牌、退市、被 ST、上期未成交单可补），不出调仓清单。这消除一整类无价值工作。

### Q7 · `urgency` 字段目前没有产生它的规则

设计规格 §6.3 输出契约含 `urgency` 字段，示例值 `"normal"`，但全文未定义其判定依据。在周频、T+1 开盘一次性成交的语义下，所有 order 的紧急度本应相同 —— 这个字段目前是悬空的。

**但用户确实需要它**：集合竞价窗口只有 10 分钟，周一早上必须知道先下哪几笔。

**处置**：保留字段并定义判定依据（FR-P3-08，P1）。建议规则（交架构师评估可行性）：

1. 卖出优先于买入（先腾出资金）；
2. 权重变化幅度大的优先于小的；
3. 流动性差的优先于好的（差的更需要早挂单）。

若架构师认为规则无法稳定实现，**则删除该字段**，不保留一个没有语义的字段。

### Q8 · 执行时点表述与回测成交假设不一致，会产生系统性滑点

这是一处会直接造成实盘与回测偏差的表述矛盾：

- D6 规定：**T+1 开盘价成交**。
- §6.3 的 `execute_note` 写：**"周一开盘集合竞价后执行"**。

要拿到开盘价，必须参与 **9:15–9:25 的集合竞价**。"集合竞价后执行"意味着 9:30 之后下单，那时成交价已经是连续竞价的即时价格，不是开盘价。

**后果**：回测按开盘价成交，实盘在开盘后成交。两者的差额不是随机噪声 —— 在上涨日尤其呈现稳定的负偏差（追涨买入）。这会形成一个**长期存在、方向一致、且完全无法从回测中看出来的收益漏损**。

**处置（需在 M3 启动前裁决）**：

1. `execute_note` 改为「周一 9:15–9:25 集合竞价阶段挂单」；
2. `limit_price_range` 的语义明确为「**集合竞价的挂单价格区间**」，而非"开盘后的限价单价格"；
3. FR-P6-02 的移动端清单必须在顶部显著标注该执行窗口 —— 这是唯一能让用户在正确时间做正确动作的地方。

这条改动的文字量极小，但不改会形成永久性的实盘-回测偏差。

## 11. 免责与风险提示

> **本章内容必须原文展示在产品的信号看板首屏、回测报告页首、每份 LLM 生成报告的页脚。见 FR-P6-04 与 AC-19 的展示位置要求。**

### 11.1 产品性质声明

**本系统是个人投资研究工具，不是持牌投资顾问产品。**

- 开发者与运营者**不具备**证券投资咨询业务资格。
- 系统的任何输出**不构成投资建议、不构成任何证券的买卖要约或要约邀请**。
- 系统输出的所谓"调仓清单"，其准确性质是：**基于历史数据统计规律的量化模型计算结果**。它是一个数学模型在给定输入下的输出，不是任何形式的专业意见。

### 11.2 关于历史回测

- **回测结果不代表未来收益。** 历史上有效的统计规律可能在未来任意时点失效，且失效通常不会有预警。
- **回测结果不等于实盘收益。** 回测无法完整刻画：真实的冲击成本、极端行情下的流动性枯竭、涨跌停与停牌的全部情形、用户手工执行产生的时点偏差与滑点、用户主观否决信号的行为影响。
- 回测使用的历史数据可能包含数据源本身的错误。系统的双源交叉校验只能降低这类风险，不能消除。

### 11.3 关于模型局限

- 系统**不预测任何个股的绝对价格或市场点位**，也不具备这个能力（见 N1）。
- 宏观择时层基于极有限的历史样本（约 180 个月频观测点），其判断的统计可靠性低（见 §10 Q3）。
- 系统**不理解**任何公司的业务、不掌握任何非公开信息、不对突发事件（业绩暴雷、监管处罚、退市、重大诉讼）具备预判能力。
- LLM 生成的文本可能包含错误。它对信号的解释来自因子数值，但其自然语言表述本身**不保证准确**。

### 11.4 使用者责任

- **所有投资决策由使用者本人做出，所有盈亏由使用者本人承担。**
- 使用者应当在执行任何一笔交易前独立判断其适当性。
- 系统不承诺任何收益率，不承诺跑赢任何基准，不承诺资金安全。
- 使用者应确保投入资金为其可承受全部损失的闲置资金。

### 11.5 传播限制

- 本系统仅供部署者本人使用。
- **禁止**将系统输出的信号、清单、报告以任何形式向第三方提供、发布、销售或分享。
- 向不特定对象提供证券投资分析、预测或建议属于需要牌照的经营活动。违反此项的法律后果由行为人自负。
